## 專題簡介

人在室內安排外出或曬衣時，需要查閱目的地與預計時段的天氣。決定是否使用冷氣、除濕機或在室內晾衣時，也需要了解房間目前的溫濕度。本專題擬整合單一房間的感測資料、中央氣象署鄉鎮預報與使用者回饋，讓每項建議都能追溯到對應的地點、時段與資料來源。

| 使用情境 | 代理人預計提供的資訊 |
| --- | --- |
| 室內設備使用 | 根據房間的溫濕度與近期變化，說明何時可考慮使用冷氣或除濕機。設備由使用者操作。 |
| 外出安排 | 查詢目的地與時段的預報，說明氣溫及降雨條件，提供行前提醒。 |
| 室內晾衣與戶外曬衣 | 比較室內濕度與戶外降雨條件，協助選擇地點或時段。 |

室內溫濕度可能因開窗、活動或家電運轉而改變。系統偵測到持續變化時，會依詢問間隔請使用者確認，將操作與回覆時間連回事件。未回覆或不確定的事件保留為未知，供後續整理與評估。

## 系統設計

第一版規劃以 ESP32 量測室內溫濕度，經 MQTT 傳送並寫入 SQLite。室外資料取自中央氣象署開放資料，查詢時以行政區與預報有效時段配對。Python 負責檢查資料品質、計算趨勢與辨識候選事件。代理人依問題選擇允許的查詢工具，套用具來源的領域規則，再透過 Web 介面說明建議與限制。

- **生活建議查詢**：核對所需資料的地點、時段及新鮮度，再輸出建議與依據。缺少必要資訊時，請使用者補充或說明資料限制。
- **背景監測與回饋**：合併持續變化的事件，依詢問間隔發出確認，將操作、回覆與未知狀態存回事件紀錄。

第一版的感測範圍為單一房間。熱舒適、衣物乾燥及設備操作原因仍受其他條件影響，回答應說明量測限制。感測器型號、MQTT Broker、Web 框架及模型供應商依實作結果記錄於設計文件。

## 評估與結果

| 評估問題 | 預定比較與觀察 |
| --- | --- |
| 回饋能否協助辨識設備操作？ | 以相同的保留事件比較固定規則與簡單分類器，記錄各類事件數、precision、recall、macro-F1 與混淆矩陣。 |
| 能否減少重複詢問？ | 在相同事件上比較基礎詢問與事件合併及詢問間隔，觀察詢問數、回覆率與重複詢問率。 |
| 建議是否有可追溯的依據？ | 以相同案例比較固定模板與工具代理人，檢查來源、時段、資料值、設備狀態與缺資料時的處理。 |

期末將依完整事件與時間切分資料，記錄資料來源、重現方式、實際結果、失敗案例與限制。公開的室內佔用資料可用於檢查前處理流程，設備操作辨識則以本專題蒐集的操作與確認紀錄評估。
